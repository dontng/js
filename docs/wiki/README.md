# 名词

这里用简短的话解释软件、硬件和通信名词。一词一页，点击名词就能跳到对应解释；每页末尾列出引用它的其他名词，也可以返回本目录。

## 从哪里看

- 写软件：[上位机](%E4%B8%8A%E4%BD%8D%E6%9C%BA.md)、[Python](Python.md)、[Qt](Qt.md)、[PyQt](PyQt.md)。
- 连接设备：[USB](USB.md)、[COM口](COM%E5%8F%A3.md)、[串口](%E4%B8%B2%E5%8F%A3.md)、[串口助手](%E4%B8%B2%E5%8F%A3%E5%8A%A9%E6%89%8B.md)、[CAN盒](CAN%E7%9B%92.md)、[驱动](%E9%A9%B1%E5%8A%A8.md)、[SDK](SDK.md)。
- 理解通信：[CAN](CAN.md)、[CAN FD](CAN%20FD.md)、[BRS](BRS.md)、[CANopen](CANopen.md)、[报文](%E6%8A%A5%E6%96%87.md)。

先从上位机或串口助手看起，沿解释中的相关词跳转即可，不要求一次读完。

## 怎样使用与维护

使用普通 Markdown 相对链接，在 GitHub 中即可点击，无需 Obsidian 或插件。正文链接说明名词之间的关系，页尾“哪些名词与它有关”列出引用当前名词的页面，提供反向跳转。反向列表是写在文件里的内容，并非 GitHub 自动生成；以后改动关联时同步维护。

本目录内的所有 Markdown 链接都指向本目录的文件，不跨到其他笔记、需求或实验。参考来源用纯文本网址保留，供需要时复制查证，不做成文内跳转链接。其他目录保持原样，只从 docs 的学习页提供一个普通入口。

每页用几句话说清含义、当前用途和容易混淆的地方；只链接有解释关系的名词，不把所有词互相连满。增加名词时检查目标页存在，并更新被引用页面的反向列表。这里只放通用解释，不放个人资料、内部原件或实验记录。

具体设备是否支持某种接口或参数，仍需看对应型号的说明；通用名词解释不等于实机验证。

## 待解释

目前没有待解释名词。以后在本节用普通列表收词，例如“- 新名词”，暂不创建空页或空链接。有了简短解释页后，把它移到上面的分类入口并补齐正文和反向关联。链接点亮表示有解释可查，不表示本人已经掌握。

## 检查

在项目根目录运行：

```bash
python docs/wiki/check/links.py
```

脚本只读取 wiki 顶层的名词页和本目录文件，不改写内容。它检查失效或越界链接、空壳解释页、目录是否漏收名词、正文引用有无反向链接，并提示已有解释但正文未链接的位置。脚本本身保存在 check 子目录，不算名词页。

名词标题即文件名，待解释名词只记在本页“待解释”列表，不另建数据库。新增解释后运行检查，由维护者核对并补链接；脚本不会猜测尚未收录的术语，也不会替代内容审核。漏链接按每页每词提示一次，同页已经链接过的词不重复提示，重叠名称优先匹配较长名称，标题、代码、已有链接和来源行不参与提示。只支持这里使用的普通行内 Markdown 链接，不作为通用 Markdown 解析器。
