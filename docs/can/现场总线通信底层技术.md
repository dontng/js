## 一、总线本质与“仲裁（Arbitration）”机制

### 1. 概念溯源
* **起源**：英文 **Arbitration**，法律上指第三方调解争议；在电子工程中指**“多主竞争同一物理介质时的路权决议”**。
* **物理矛盾**：若采用点对点专线，线束成本与重量无法承受。总线（Bus）让所有节点挂在同一对差分双绞线（$CAN\_H$ / $CAN\_L$）上。同一微秒内，线缆只能容纳一种电平状态。

### 2. 硬件裁决逻辑：“线与（Wired-AND）”机制
* **显性电平（Dominant，逻辑 0）**：芯片内部开关闭合，强行建立线间压差（$V_{diff} \approx 2.0\text{V}$）。
* **隐性电平（Recessive，逻辑 1）**：芯片内部开关断开，仅靠终端电阻被动拉平压差（$V_{diff} \approx 0\text{V}$）。
* **物理规则**：显性电平绝对压制隐性电平（“0” 战胜 “1”）。

### 3. 逐位仲裁过程（Bit-wise Arbitration）
假设节点 A（ID: `0x01`，二进制高位补零 `00000000001`）与节点 B（ID: `0x02`，二进制 `00000000010`）在同一纳秒发起发送：
1. 节点 A 与 B 边发送电平，边通过内部回环引脚监听总线真实电平。
2. 前 9 位两者均为 `0`，总线保持显性，双方均认为通信正常。
3. 到第 10 位：
   * 节点 A 发送 `0`（显性拉低）；
   * 节点 B 发送 `1`（隐性释放）。
4. **决议瞬间**：总线呈现 `0`。节点 B 发现自身发出的是 `1` 但总线为 `0`，判定有更高优先级节点在线，**硬件在 1 比特时间内立即切断发送端，转入纯监听接收模式**。
5. **结论**：**ID 数值越小，特权等级越高。**仲裁全程无损，获胜者毫无感知且无需重发。

## 二、经典 CAN vs CAN FD vs CAN FD 加速（BRS）

| 维度 | 经典 CAN (Classic CAN) | CAN FD (普通模式) | CAN FD 加速 (BRS 模式) |
| :--- | :--- | :--- | :--- |
| **单帧最大载荷** | 8 字节 | 64 字节 | 64 字节 |
| **仲裁段速率** | 通常最高 1 Mbps | 通常最高 1 Mbps | 通常 1 Mbps |
| **数据段速率** | 恒定（最高 1 Mbps） | 恒定（最高 1 Mbps） | **动态升频（2 Mbps ~ 5 Mbps）** |
| **核心优势** | 极强抗噪、允许长距离 | 一帧装下复杂控制环数据 | 极限压低大载荷传输时延 |

### 1. 双速率切换（Bit Rate Switch, BRS）
CAN FD 加速报文的时间轴演进机制：

$$\underbrace{\text{SOF + 仲裁段 (ID)}}_{1\text{ Mbps (路权争夺，需等待电平往返传播)}} \xrightarrow{\text{BRS=1}} \underbrace{\text{数据载荷 (Payload: 最大64B)}}_{5\text{ Mbps (单节点独占，高速倾倒数据)}} \xrightarrow{} \underbrace{\text{CRC定界 + ACK段}}_{1\text{ Mbps (降速确认，握手收尾)}}$$

* **Tx: CAN FD 与 Rx: CAN FD 加速的差异**：
  * 若上位机发送的配置中 `BRS=0`，Tx 便保持普通 CAN FD（1M 到底）；
  * 若驱动板固件内将寄存器标志位设为 `BRS=1`，则 Rx 回传时数据段被倍频至 5M，界面识别为“CAN FD 加速”。

### 2. 为什么 BRS 不被设计为默认强制开启？
* **高频电磁辐射（EMI）激增**：5 Mbps 下信号上升沿极其陡峭，极易辐射杂波并受电机高频 PWM 串扰。
* **物理线长极限衰减**：1 Mbps 下总线可延伸至 $20\sim 40\text{ 米}$；5 Mbps 下由于信号反射与高频衰减，有效拓扑通常受限在 $3\sim 5\text{ 米}$ 以内，且严禁过长支线（Stub）。

## 三、帧结构、物理定界与位填充（Bit Stuffing）

在上位机数据列表中，定界符与校验段被硬件屏蔽。底层实际通过严苛的物理电平法则划定边界：

```
┌──────┬──────────────┬──────────────┬──────────────┬──────────────┬──────┐
│ SOF  │ 仲裁段+控制域 │ 数据段(0-64B)│   CRC 校验码  │  ACK 槽/定界  │ EOF  │
└──────┴──────────────┴──────────────┴──────────────┴──────────────┴──────┘
  ▲                                                                   ▲
  └─ 强行拉低 1bit (显性0)                                 连续 7bit 隐性1 ─┘
```

1. **帧起始（SOF）**：总线空闲全为隐性 1。发报文第一位强行拉低为**显性 0**，其下降沿使全网节点执行硬同步（Hard Synchronization）。
2. **帧结束（EOF）**：整帧结尾强制打出**连续 7 个隐性 1**。
3. **位填充法则（Bit Stuffing）**：
   * 在 SOF 到 CRC 之间，一旦硬件检测到连续 **5 个相同电平**，发送端强制插入 **1 个相反极性的填充位**；接收端自动将其剥离。
   * **定界保证**：正因位填充的存在，数据内部绝对不可能自然出现连续 6 个或 7 个相同的电平。因此，连续 7 个隐性 1（EOF）具有不可伪造的绝对定界效力。

## 四、时延模型与硬件级错误处理机制

### 1. 为什么 CAN 不需要像 TCP/IP 那样动态测量 RTT？
* **物理尺度微小**：机械臂或机器人线长一般为 $1\sim 2\text{ 米}$，光电传播延迟仅约 $5\sim 10\text{ ns}$，在微秒级电控系统中趋近于零。
* **强确定性（Deterministic）**：无操作系统协议栈排队与未知跨网路由，传输时长严格由波特率、填充位及节点硬件中断响应周期决定，往返时延在工程设计期即可精确固化为常数。

### 2. 硬件 CRC 与瞬态重发
* **多项式保障**：经典 CAN 采用 15 位硬件 CRC；CAN FD 升级为 17 位或 21 位 CRC，芯片硬件漏检率低于 $10^{-14}$。
* **主动错误破坏机制**：
  * 接收节点一旦校验失败或发现填充规则违背，立即在当前位打出**连续 6 个显性 0（错误帧，Error Frame）**破坏整条总线。
  * 发送端芯片检测到总线畸变，在下一个空闲槽**由硅片自动重新投递**，全过程无需上层 CPU 与软件介入，微秒级恢复。

## 五、为什么现代工业与仪器仍保留经典 CAN？

1. **极端物理距离需求**：
   * 楼宇电梯、光伏储能电站集装箱、大型工程机械布线长达数十米至上百米，高频 CAN FD 在物理上无法克服信号反射与高频衰减，必须降至 $50\sim 250\text{ kbps}$ 经典 CAN 才能运行。
2. **被动传感器带宽过剩**：
   * 温度采集、倾角传感器、压力变送器每秒仅上报几个字节，经典 CAN 8 字节载荷已有充足余量，更换 CAN FD 无法带来任何系统收益。
3. **工业生态兼容与防破坏保护**：
   * J1939 与标准 CANopen 拥有数十年的存量设备资产。若在旧网络中强行混入 CAN FD 设备，老节点会将新报文识别为总线格式畸变，进而狂发错误帧瘫痪整网。
4. **认证与安全壁垒**：
   * 医疗器械与轨交设备核心部件若已通过长达数万小时的 SIL3/ASIL-D 认证，其“不坏不修、非必要不升级”的可靠性法则高于对新速度的追求。
