# 需求与问题管理

这里记录：**我想做什么、为什么做、现在在问什么、下一阶段要解决什么，以及哪些问题已经有证据地解决。**它不是知识笔记或聊天全文备份。

更新：2026-11-02。初始整理为 **7个阶段、28个主线问题**，可随实践增删、拆分、合并与调整顺序；全部尚无本人实作验收记录。部分概念已有讨论，不能因此标为已掌握。

## 自我迭代方式

**提出 → 拆分 → 暂定回答 → 本人验证 → 回看修正 → 下一问**。完整做法见[迭代规则](ITERATION.md)，复杂问题可用[问题模板](QUESTION_TEMPLATE.md)。28问只是起步种子，阶段是导航，不是锁死的课表。AI负责协助整理，你逐步获得解释、修改和判断的能力。

## 三个入口

- [需求与已有决定](GOALS.md)：保留用户真实目标、约束与已确定方向。

## 怎样维护

问题使用稳定编号，如 P01-Q01；跨阶段移动保留编号并说明去向，不悄悄换号。新问题先收件，归类后原收件项保留去向，避免消失或重复。
每次只把一个问题选进[当前任务](../docs/CURRENT.md)。需求与问题在此管理，答案放 learning，验证放 labs，稳定实现放 tools，用链接串起来，不重复抄长文。

问题状态采用：待解决、推进中、待验证、已解决、暂缓；需要时标记已拆分、合并或重新打开，并保留原因和去向。已有讨论但未实作通常为待验证；已解决必须链接证据，并说明本人能解释、能修改、能验证、能排错到什么程度。概念问题可用本人解释记录作证，不能伪称实机通过。

用户原始需求、AI归纳、训练建议要区分；GitHub发现的功能是候选，不自动算用户要求。原话不逐字搬入公开仓库，工作案例仅保留可公开的一般问题。
